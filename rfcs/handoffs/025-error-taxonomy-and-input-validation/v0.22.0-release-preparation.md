## 0. What this is

The v0.22.0 slices (Q3d, Q1c, Q3b, Q3c, Q2f, Q3e, Q10) are local commits; the architect's documentation commits
are interleaved with them. This task makes the tree a release candidate and **pushes everything once**. The
release itself (tag, publish, date) is the owner's, through the `Release` workflow; nothing here tags or
publishes. Do not rebase, reorder, squash or amend any local commit: the stack is pushed as it is
(`git log --oneline origin/main..HEAD` is the list; report it).

## 1. The change (one commit: `chore: prepare v0.22.0 (version, install examples, changelog)`)

1. **Version.** `Cargo.toml` `[workspace.package].version` → `0.22.0`; `Cargo.lock` follows
   (`cargo update -w` or the edit `cargo` makes; the two workspace packages only; report the lockfile diff).
2. **Install examples.** Every `localcache = "0.21.6"` / `{ version = "0.21.6", … }` line in `README.md` and
   `docs/src/` becomes `0.22.0`. `python3 scripts/check_versions.py` is the gate (it fails on any stale line and
   on a missing CHANGELOG section); do not search by hand only.
3. **Documentation that speaks of 0.22 in the future.** `git grep -n -i "0\.22\|will be removed\|will be rejected\|announced\|from v0.22" -- docs/src README.md crates`
   and rewrite every sentence that is true only before the release ("will", "from v0.22.0 …", "plan",
   "announced in 0.21.5") into what is true at 0.22.0. `docs/src/roadmap.md` is the architect's: leave it, and list
   what you saw in it. **Re-read each page you touch in full.**
4. **`CHANGELOG.md`.**
   - Rename `## [Unreleased]` to `## [0.22.0] — Unreleased` and add `*Date set at owner authorization.*`; fix the
     two link references at the bottom (`[Unreleased]` compares `0.22.0...HEAD`; add `[0.22.0]` comparing
     `0.21.6...0.22.0`); a fresh empty `## [Unreleased]` is **not** added (v0.21.6 did not either).
   - A summary block at the top of the section, as v0.21.6 and v0.21.5 have: **"A breaking release."**, who is
     affected, and **one consolidated migration list**, one line per breaking change with a link to its entry
     below: `Database` wraps the opaque `DatabaseError`; `rusqlite` 0.40.2 (and `links`); seven variants replace
     `UnsupportedFeature` and `PayloadVersionMismatch`; the four newly rejected inputs (`max_entries(0)`, TTL
     under one second, oversized `batch_set`, oversized imports); `run()` returns an undecodable entry's error;
     `JournalMode::Preserve` is the default and `JournalMode` is `#[non_exhaustive]`; imports honour
     `max_entries`; the removals (list them); the `Poisoned` resource value; `max_decompressed_bytes` /
     `PayloadTooLarge` with `compression`; the CLI `migrate` command removed. Check the list against the
     individual entries; none may be missing or duplicated.
   - **Known issues**: copy the paragraph in review 056 § 3 **verbatim**
     (`.git-exclude/reviewed/056-architect-design-decision-bincode-string-length-claim-2026-10-31.md`).
   - Keep every existing entry; order headings Keep-a-Changelog style (`Added`, `Changed`, `Removed`, `Fixed`,
     `Security`) as they already are.
5. **Nothing else.** No code, no schema, no wire-format change, no dependency change, no MSRV change.

## 2. Gates (all, on the committed tree)

`cargo fmt --all --check`; `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`;
`cargo make gate-features`; `cargo test --workspace --all-features --locked --no-fail-fast`;
`RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps --locked`; `cargo make gate-versions`;
`rustup run 1.85.0 cargo make gate-msrv`; `cargo make gate-deny`; `cargo make bench-compile`; `cargo make
gate-docs` and `cargo make gate-archive` (they need a committed tree: this is the first time they run on the
release content); `mdbook build docs`. Report each with its exit code and the test totals.

## 3. The push, and the release candidate

1. Show `git log --oneline origin/main..HEAD` and `git status` (clean). Push with a plain `git push`
   (fast-forward only; never force). The book deploys from `main` on this push, so everything it describes is
   the release content.
2. Report: the CI run id and its result (**expect the nine jobs green**), the Docs run id (and that the deployed
   book shows the new pages: check one page that changed, for example `errors.md`'s v0.22.0 migration notes),
   then **dispatch `msrv-fresh` and `advisories`** and report both run ids and results. This is the release
   candidate. If anything is red, fix it in a new commit on top and say so; never rewrite the pushed history.
3. **Do not** run the `Release` workflow, create a tag, publish, or set the date. The architect gives the Go or
   No-Go from your evidence plus an independent check; the owner authorizes the date and the version choice.

## 4. Also before the push: the `preload` measurement

If not already done (it is due before the RC): the quiet-host measurement of ROADMAP's deferred-register row
"`preload` costs about 235 µs per entry at 1M…". Report only (no code): method, host load and swap before and
after, results on the K2 commit and on the `0.21.5` tag and on this tree. If it reproduces a regression, stop and
file a design request; if it does not, the architect updates the performance page's wording.
