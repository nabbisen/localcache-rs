## 2. The proof that the format is unchanged (the point of the task), each with its evidence

* **Known answers.** The AES-256-GCM known-answer tests of NIST (the project's own vectors if it has them) pass on the port; and a differential check in both directions between the **published 0.26.0** `localcache-format` and this tree: for at least 2,000 random (key, nonce, associated data, plaintext) tuples over the lengths 0, 1, 15, 16, 17, 4095, 4096 and 1 MiB, sealing with one and opening with the other gives the same plaintext, and a seal with a fixed nonce gives the **same bytes** (the library's own nonce is random in production; the check uses the lower-level primitive with a fixed nonce, as in request 078 § 6).
* **The four stored tags, keyed and unkeyed.** As request 085 § 1: the published 0.26.0 and this tree each write 40 entries per combination (`*-aes256gcm-bound` forms included), each reads the other's file; tags equal; keyed lengths equal; **0 failures** reported with the count of checks.
* **Rotation and import.** A database sealed by 0.26.0 is rotated by this tree under the same key and read by both; a keyed import of a record bound to its path from 0.26.0 is accepted, one bound to another path is refused, as before.
* **Tampering.** A flipped bit in the ciphertext, the tag, the nonce, the associated data (path) and a wrong key: each is refused with the **same public error and text** as in 0.26.0 (the pinned error table passes unchanged).
* **The golden vectors, the digest test, fuzz `open` and `from_slice` (ten minutes each) and Miri** on `localcache-format` as in request 085; the sealing code changed, so run them.
* **`Key` and zeroization.** The `Key` type's `Debug` does not print, it is zeroized on drop: its tests pass; say whether `aes-gcm 0.11` or `ctutils` changes what the library keeps of the key in memory (read its `Drop`/`zeroize` support; claim only what you read).
* **Timing.** The new library's constant-time behavior is the reason for the bump. Do not benchmark security; do report a measurement of `set` and `get` of a 64-byte and a 1 MiB keyed entry against 0.26.0 in the style of request 080 (host, load, paired runs), with no promise.
