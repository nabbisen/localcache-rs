## 0. What this release is

A **patch** under the SemVer policy: no new API, no behaviour change a caller can see except what is listed. It carries four things:

1. **Performance:** the payload encoder's 21 inlined writers (a 1 MiB `Vec<u8>` `set` about 4.2× faster on the measured host).
2. **Dependencies:** `base64 0.23` (one changed error text, see § 1.2) and the unused `tokio-test` line removed.
3. **Documentation:** the performance page ("Large payloads and your release profile"), the known issue of the bundled SQLite and the compile-options section (request 079), and the rustdoc fix already on `main`.
4. **An announcement:** v0.26.0 removes the `opentelemetry` feature and the `async-std` feature. This release only says so. **Nothing is removed, deprecated in code or warned about at build time.** (A Cargo feature cannot carry `#[deprecated]`, and a `compile_error!` would break the users it is meant to warn.)

The MSRV raise is **not** announced here as a separate item: RFC 023 R3.1 announces a security raise in the release that makes it. The known-issue paragraph of `docs/src/security.md` already says what is known today. Do not add a promise about v0.26.0's contents beyond the two removals.

Nothing here tags, publishes or sets the date.

## 2. Verify, each with its evidence

* **Public API against the `0.25.0` tag** (`git archive`, `cargo doc -p localcache --all-features --no-deps --locked` of both): no difference (state it), or each difference listed.
* **Stored bytes and compatibility with the published `0.25.0`:** both ways, all four tags, compressed and not, keyed and unkeyed; the stored tags and content byte counts equal; the committed fixtures migrate to byte-identical dumps. (The encoder change touches the hot path of every `set`; this is the evidence that the bytes did not move.)
* **The golden vectors and the fuzz targets** of `localcache-format` on the final tree (the encoder is the changed file): the vectors pass; the fuzz targets run at least ten minutes each without a crash; Miri on the format crate's tests as the book's command states, if the toolchain exists.
* **`cargo package --workspace --locked` and `cargo publish --workspace --locked --dry-run`** from a clean checkout of the committed tree: exit 0 for three crates in the order `localcache-format`, `localcache`, `localcache-cli`; package file counts and sizes.
* **MSRV:** `rustup run 1.85.0 cargo make gate-msrv` exits 0 (the base64 change must not need a newer compiler).
* **`cargo make gate-deny` immediately before the push** (and again if more than a day passes before the dry run; a yank means stop and report).
* **The release workflow's dry run from `main`** after the push: the digest step must print exactly three lines, in the order `localcache-format`, `localcache`, `localcache-cli`.
