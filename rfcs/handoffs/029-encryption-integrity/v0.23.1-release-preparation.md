# v0.23.1 Release Preparation Handoff

Scope: RFC 029 R4 and R5 and the announcement of v0.24.0 (Q14, reviewed in `.git-exclude/reviewed/083-architect-q14-review-2026-11-03.md`). The two Q14 commits are the only unpublished work.
Precedent: `rfcs/handoffs/026-use-order-and-one-path-index/v0.23.0-release-preparation.md`.
Format of the review request: `rfcs/handoffs/025-error-taxonomy-and-input-validation/implementation-handoff.md` § 6.
Authorship: high-capability model. Authorized: the owner (RFC 029 and its two-release delivery; the date is authorized separately, after the release candidate).

## 0. What this is

This task makes the Q14 commits a release candidate and pushes them **once**. Nothing here tags, publishes or sets the date. Do not squash or amend; a rebase onto `origin/main` is the only history change.

## 1. The change

1. **Rebase** onto `origin/main` first (`git fetch`, `git rebase origin/main`). Resolve nothing by hand beyond what the Q14 files require; if a file you did not change conflicts, stop and report.
2. **Version, as its own commit `chore: prepare v0.23.1 (version, install examples, changelog links)`.** `Cargo.toml` `[workspace.package].version` → `0.23.1`; `Cargo.lock` follows (report its diff in full: besides the two workspace packages it already carries `zeroize`). Every install line in `README.md` and `docs/src/` → `0.23.1`
   (`python3 scripts/check_versions.py` is the gate). In `CHANGELOG.md` the `[0.23.1]` section exists; add the link references at the foot (`[Unreleased]` compares `0.23.1...HEAD`, `[0.23.1]` compares `0.23.0...0.23.1`). The date line stays `*Date set at owner authorization.*`.
3. **Verify the `[0.23.1]` section against the tree and correct only what is untrue.** At least, each with its evidence:
   * the public API is unchanged in item names and signatures (build `cargo doc -p localcache --all-features --no-deps --locked` of `git archive 0.23.0` and of this tree and compare, as for 0.23.0; the expected differences are doc text and the `Debug` impl's body);
   * **no stored byte changes, across versions, both ways:** a database with encrypted entries (all four tag variants, compressed and not) written by a build of the `0.23.0` tag is read by this tree with the same key, and one written by this tree is read by the `0.23.0` build; rotation by this tree of a database written by `0.23.0`, then read by `0.23.0` with the new key;
   * `zeroize` appears in the dependency graph only with the `encryption` feature (`cargo tree -p localcache --no-default-features -e normal` and with the feature, before and after);
   * `zeroize 1.9.1` resolves at MSRV 1.85 with a fresh lockfile (`cargo make gate-msrv` and the `msrv-fresh` workflow);
   * no other type can print the key (your step 0 § 6 still holds after Q14: rerun the compile-time `Debug` probe on the final tree).
4. **Documentation that would be untrue after the release.** `git grep -n -i "v0\.23\.1\|0\.23\.1\|announced\|will be\|planned\|next release\|upcoming" -- docs/src README.md crates`: list every hit with a verdict. "From v0.23.1 …" and "Fixed in v0.23.1" are true after the release and stay; sentences in the future tense about v0.24.0 stay. `docs/src/roadmap.md` and `ROADMAP.md` are mine.
5. **Dependencies.** `cargo make gate-deny` immediately before the push, and again if more than a day passes before the dry run. A yank means stop and report.

## 2. Gates and the push

All gates of Q14 § 4 plus `gate-docs`, `gate-archive` and `mdbook build docs`, on the committed tree. Then `git log --oneline origin/main..HEAD` (report it), a plain `git push`, and: CI and Docs green; dispatch `msrv-fresh` and `advisories`; when both finish, dispatch the `Release` dry run from `main` and read the log of "Record the .crate digests" (report the two lines). That is the release candidate.

## 3. The request

One review request: the rebase result, the version commit and the `Cargo.lock` diff, the verification table of § 1.3 (each check with its result), the grep verdicts of § 1.4, the gates, the run ids and the digests.

## 4. Not yours

The date, the tag, the real `Release`, `ROADMAP.md`, `docs/src/roadmap.md`, any change to the crate's code.
