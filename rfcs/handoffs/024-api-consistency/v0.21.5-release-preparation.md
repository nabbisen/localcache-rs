     - honest names, with deprecations pointing to their replacements (name the book's migration

   - **Look ahead: v0.22.0 (breaking)**, the reason this summary exists in this form. Each item in
     one sentence, and each exactly as decided in its RFC:
     - `rusqlite` 0.39 → **0.40.2** (bundled SQLite 3.51.3 → 3.53.2). **Not an MSRV change.** A
       crate that depends on `rusqlite` directly must use 0.40.2 or later with localcache 0.22,
       because of `links = "sqlite3"` (RFC 023 R9);
     - errors: `UnsupportedFeature` and `PayloadVersionMismatch` are removed; seven purpose-named
       variants replace them; `Database` wraps an opaque `DatabaseError` (RFC 025 R3–R5, R7);

       import with more distinct entries than `max_entries` (RFC 025 R6; RFC 024 B3);
     - behaviour: `QueryBuilder::run()` returns the first undecodable entry's error, and
       `run_report()` is the way to tolerate them (RFC 024 B1); an engine that does not choose a
       journal mode leaves an existing database's mode unchanged (B2); imports honour
       `max_entries` (B3);
     - removals: everything deprecated in 0.21.5 except `drop_path_index`/`list_path_indexes`;
       the CLI's `migrate`; and the two observable strings that still name `ConnectionPool`
       (RFC 024 B4).

     with a schema change. It will be announced in detail one release ahead. Do not describe it
     further: RFC 026 is not written.

## Part B — Paired re-measurement of the query rows

### B.1 — Why

`docs/src/performance.md` publishes query figures whose code path changed after 0.21.4:
- Q2d rebuilt the materialization loop to record skipped entries, returning a `QueryReport`;
- Q2b moved it into `crates/localcache/src/cache/query/execution.rs`;
- Q3a routed `get_if_fresh` and `cleanup_expired` through `ttl_remaining`.

Phase 24 exit criterion 6 requires the docs to match the code.

Rows under test:
- **`limit(25)`, no field predicate**;
- **`field_gt` + sort by `SortKey::Field` + `limit 25`**;
- **`path_in_dir`, non-recursive**;
- **`path_glob`, leading wildcard**;
- **`cleanup_expired`**.

Controls:
- `get`, which did not change;
- `get_if_fresh`, whose change is one saturating subtraction;
- `batch_set`, which did not change since 0.21.4.

### B.2 — Method: the P1d paired comparison, **extended from the start**

This follows review 013 K2, so the question gets settled by samples, not argument.
1. Two builds in one session:
   - a detached worktree at tag **`0.21.4`** (before);
   - the Part A commit (after).
2. The harness, `crates/localcache/benches/scale_profile.rs`, changed after 0.21.4 **only in the
   spelling** of its sort call (Q2c: `order_by_field(…, false)` → `order_by(SortKey::Field(…),
   SortOrder::Desc)`). Show `git diff 0.21.4 -- crates/localcache/benches/scale_profile.rs`, and
   confirm that no timed region changed.
3. Scale 1M, on real storage, with `TMPDIR` under `.git-exclude/tmp/`. **Matched stored-path
   length:** check both arms' `TMPDIR path length` and `example stored path length` lines before
   reading any timing.
4. **One warm-up run, discarded.** Then eight interleaved runs: before, after, before, after,
   before, after, before, after.
   *(Corrected 2026-09-24, review 025 K2: every run must also set
   `LOCALCACHE_SCALE_QUERY_REPEATS=5`. The harness's limitation 5 says single-run whole-namespace
   query figures are unverified until replicated. The first session omitted it, because this
   handoff did not ask for it.)*
5. Per row, compare the per-arm **medians** of four samples each.

### B.3 — Decisions

- **Controls** (`get`, `get_if_fresh`, `batch_set`): within ±10% means the session is clean.
  Otherwise **stop and report**.
- **Each row under test:**
  - after-median within **5%** of before-median: the published row stays. Record the ratio;
  - more than 5% **slower**: **stop and report**. The architect decides whether a cost is
    acceptable, and how to document it, before release;
  - more than 5% **faster**: the published row may be refreshed from one fresh run at the page's
    stated path length, replacing the whole row, never splicing. Propose it in the request; do
    not edit the page unasked.

Put the raw logs under `.git-exclude/tmp/` (`q2r-warmup.log`, `q2r-before-run1.log`, …), cite them,
and do not paste them.
