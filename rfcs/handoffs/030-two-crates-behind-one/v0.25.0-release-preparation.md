## 0. What this is, and why the order matters

This task makes the nine commits a release candidate and pushes them **once**, together with the version commit. Request 070 § 8 found that `gate-docs` (and so the CI job "Docs") fails on any commit that contains the new dependency while the workspace is still `0.24.0`: the last step packages `localcache-cli` against the published `localcache 0.24.0`, whose source still names `zstd`. Review 093 chose your option (1): do **not** push the nine commits before the version commit; push them as one stack ending in `chore: prepare v0.25.0`. Nothing here tags, publishes or sets the date. Do not squash or amend commits already made; `git fetch` and `git rebase origin/main` first (my documentation commits may have moved it).
